# KKFans WhatsApp 助手

Manifest V3 Chrome 扩展，用于读取 WhatsApp Web 当前会话的历史消息、为会话列表添加彩色标签、把本地数据增量备份到云端，并通过 OpenAI Chat Completions 兼容接口分析会话。

## 当前能力

- 识别普通 WhatsApp Web、WhatsApp Business Web，以及 Meta Business Suite 收件箱的 WhatsApp 页面（`/latest/inbox/wec`）。
- 切换会话后读取已挂载消息，并可自动向上滚动加载完整历史。
- 基于消息 ID 去重，消息保存到扩展自身的 IndexedDB。
- 过滤引用区、链接预览和第三方翻译插件注入的文本。
- 检测用户滚轮或点击消息区后自动暂停采集。
- 为会话添加预设或自定义标签，并在虚拟化会话列表中持续重绘。
- Chrome Side Panel 展示采集状态、消息预览和标签管理。
- 使用“用户名 + WhatsApp账号”隔离云端数据，支持云端恢复、增量上传、断点续传和自动重试。
- 本地配置模型接口地址、API Key 和模型名称，由 KKFans 服务端转发到任意 Chat Completions 兼容厂商。
- AI 根据最近聊天上下文判断 SOP 阶段、对方意图、风险、下一步动作并生成西语回复建议。

媒体消息当前只保存类型、链接和数量等元数据，不下载图片、视频、语音或文件原件。

## 本地开发

需要 Node.js 20+ 和 pnpm。

```bash
pnpm install
pnpm dev
```

生产构建：

```bash
pnpm typecheck
pnpm test
pnpm build
```

构建结果位于：

```text
.output/chrome-mv3
```

生成发布 ZIP：

```bash
npm run zip
```

每次执行都会先自动递增补丁版本（例如 `0.5.1` → `0.5.2`），并让
`package.json`、扩展 Manifest 和 ZIP 文件名保持一致；打包失败时会恢复原版本。

在 Chromium 浏览器中打开扩展管理页面，启用开发者模式，选择“加载已解压的扩展程序”，然后选择上述目录。

## 使用方式

1. 打开 `https://web.whatsapp.com/` 或 Meta Business Suite 收件箱的 **WhatsApp** 标签页，并选择一个会话。
2. 点击扩展工具栏图标打开侧边栏。
3. 会话稳定后自动增量读取已加载消息；需要更早消息时点击“补齐历史”。读取到本地不代表自动上报。
4. 在侧边栏里为当前会话打标签，标签和备注会显示在聊天列表中。
5. 自动读取期间如果在消息区滚动或点击，采集会暂停并恢复原来的视图位置。
6. 在设置页填写用户名和 WhatsApp 账号，点击“保存并恢复”。默认全部手动上报，在概览“当前会话”卡片点击“上报”，才上传该会话的已读取消息和资料。用户名和账号为必填项，账号不能包含空格。
7. 在设置页填写兼容厂商的接口地址、API Key 和模型名称，测试连接后即可分析当前会话。

云端 API 在开发构建中默认为 `http://127.0.0.1:3333`，生产构建默认为 `https://kkfans.lllin.fun`。可通过构建环境变量 `WXT_CLOUD_API_BASE_URL` 覆盖。

## 云端恢复与双向同步

### Meta Inbox 支持范围

- 两个入口使用同一操作员、同一会话标题进行联系人识别，沿用已有号码格式归一化和云端匹配，不读取右侧联系方式、不按来源新建联系人。
- Meta 专用 DOM 模块位于 `src/meta-inbox/`，页面选择位于 `src/platforms/`；消息存储、标签、备注、合作资料、AI 与上报策略复用现有流程。
- 消息以页面稳定 ID 增量读取。两种入口 ID 不同的文本/链接消息，只有时间、方向、正文唯一匹配或相邻已匹配消息提供明确依据时才关联；保留本地别名供后续读取使用。不确定的附件或重复短句不强行合并，因此不保证所有跨来源消息都能去重。
- Meta 不显示的消息保留未知类型；未显示明确时间的消息不编造日期。已经读到的时间不会被后续缺少日期分隔符的局部读取清空。Inbox 顶部不等于 WhatsApp 真正首聊起点，不覆盖已确认的首聊信息。
- 升级后需要允许新增的 `business.facebook.com` 访问权限，并刷新 Meta 页面。Messenger/Instagram 页面不会读取或上报。

- 0.5.18 起默认全部手动上报：读取消息、修改标签/备注/合作资料、定时下载和账号保存均不会自动授权上传。升级前遗留的自动上传队列会被过滤。
- 当前会话“上报”会先保存正在编辑的备注，再核对云端版本、增量上传当前会话。按钮显示上报中、上次成功时间和重试反馈。读取或恢复期间不能上报。
- 配置页“首次上报后自动同步”默认关闭、修改立即保存。开启后，仅自动更新本机手动上报成功过的会话；云端下载、旧上传记录不会自动获得上报资格。关闭后，后续修改仍需手动上报。已发起但失败的上报保留请求以支持断点重试。
- 上报开关、成功记录和待处理请求保存在本机，并随会话别名迁移；重装后需要重新指定上报。此功能不需要修改服务端协议。

- 重装后填写**原用户名和 WhatsApp 账号**，点击“保存并恢复”，恢复标签、备注、合作资料、SOP 阶段及已上传的聊天消息；未曾上传的数据无法从云端找回。
- 手动“恢复云端数据”会完整核对云端标签、备注、合作资料及 SOP 阶段，消息仍使用增量游标；后台每 5 分钟增量检查。手动恢复请求独立持久化，不依赖是否有待上传会话，下载按会话、消息顺序分页进行，中断后保留进度，失败时不会直接上传空资料。
- 设置卡片显示真实下载时间、会话资料数及消息数。旧版只有上传成功而没有下载完成记录时，显示“上传完成 · 恢复待确认”，不会当作恢复完成。
- 设置卡片的“同步步骤”区分本地检查、请求 `/download` 和写入数据；接口请求应在扩展 Service Worker 的 Network 查看。后台和内容脚本使用原生 Chromium 兼容的 `sendResponse` 回调，不依赖较新内核的 Promise 监听器支持。
- 恢复期间暂时锁定资料保存。下载数据不会触发回传循环，恢复时间不替代原消息时间。
- 首次合并保留已有本地资料；后续根据上次同步版本识别修改。同一资料双方都修改时，设置页会提示选择保留本地或使用云端冲突项，不会静默覆盖。
- 版本冲突（409）会持久化一次完整资料核对，再尝试上传；消息仍按增量读取。如果仍冲突，显示具体联系人并暂停自动上传，后台重启也不会无限重试。核对服务端状态后可点“恢复并同步”重试。
- 已删除的云端会话不会下载。0.5.9 配套服务端明确返回 `skipped: "deleted"`，插件保留本地内容并跳过该会话，继续处理其他联系人；不会把未上传消息标成已同步。设置页显示跳过数量，后续云端重新出现该联系人时恢复正常同步。仅升级插件而未部署配套服务端，无法识别旧服务端返回的删除冲突。
- 本地数据库绑定当前账号空间，不允许直接改为另一账号后上传旧数据；不同账号请使用独立浏览器环境。AI 密钥、模型配置、翻译记录及其他本机设置不参与恢复。
- 账号保存前先显示用户名和完整 WhatsApp 号码，需勾选核对并二次确认；取消不会保存新配置或向新账号发起同步。
- 会话 ID 使用操作员用户名 + 联系人号码（没有号码时使用抓取到的联系人名称），不包含头像；号码中的符号和空格不影响身份。旧本地 ID、标签备注和已上传进度会迁移。
- 无号码的同名联系人无法仅凭名称可靠区分；发现多个同名旧会话时会停止自动合并，避免串聊天。不同操作员用户名仍是独立空间，`kkflow` 与 `kkflow01` 不会自动合并。

### 服务端升级顺序

1. 先部署 `nest-vue-admin/apps/server` 的本次变更，新增 `POST /whatsapp/sync/download`，并升级上传接口的版本校验与空数据保护。
2. 执行新增索引 migration `20260903040000_add_whatsapp_message_identity_index`；只加速按会话和原始消息 ID 查询，不删除或清理旧数据。
3. 执行本插件的 `pnpm build`，在扩展管理页重新加载现有插件，再刷新 WhatsApp 页面；不需要卸载插件。
4. 在设置页点击“保存并恢复”或“恢复云端数据”，等待恢复完成；需要上传时，在当前会话点击“上报”。服务端未升级时会提示“先更新服务端”并阻止上传。

下载请求使用 `username`、`whatsappAccount`、`resource`（`conversations` / `messages`）、`since`（毫秒时间戳）、`after`（分页游标）和 `limit`（最多 200）。同步协议为 schemaVersion 9，服务端必须在下载响应中声明支持该版本，否则插件阻止上传。`metadataFields` 明确变更分组，`metadataBaseVersion` 携带已读取版本；409 后重新拉取再合并。已软删除会话不下载，本地清空消息不会删除云端记录。

服务端对同账号、同会话中的原始 WhatsApp 消息 ID 做幂等写入，不再依赖插件生成的消息 key；先复用旧记录，再为真正新增的消息生成服务端 key。不同客户端版本、不同本地会话 ID 的重复上传及批次内重复只算一次新增。已有重复消息不会被本次升级自动删除，需单独核对清理。

## 代码结构

```text
src/
  entrypoints/              WXT 的 background、content script、sidepanel 入口
  content/                  页面控制器、标签注入与弹层
  whatsapp/                 DOM 选择器、会话身份、消息解析、历史加载
  cloud/                    云端请求、持久同步队列与失败重试
  ai/                       OpenAI Chat Completions 兼容服务端客户端
  storage/                  chrome.storage 设置与 IndexedDB 消息仓库
  core/                     共享类型和运行时消息协议
  test/                     测试环境初始化
```

所有 WhatsApp DOM 选择器都集中在 `src/whatsapp/selectors.ts`，页面结构变化时优先更新该适配层。

## 隐私与限制

- 本地 IndexedDB 始终保留完整数据；配置用户名和 WhatsApp 账号后，同一份数据会备份到配置的云端服务。
- 用户名和 WhatsApp 账号是数据命名空间，不是身份认证凭据。
- AI 配置只保存在当前浏览器；分析时 API Key 和最近最多 120 条消息会发送到 KKFans 服务端，再由服务端请求用户配置的模型厂商。
- 会话使用用户名与联系人号码/名称生成稳定 ID；换头像不会产生新记录。没有号码且名称改变或重名时，仅凭可见名称无法保证身份准确。
- “读取完成”表示已读取 WhatsApp Web 界面能够向上加载的全部消息，不包含服务端已删除或当前账号无权访问的内容。
- 在商业环境使用前，请自行确认 WhatsApp 条款、客户授权和适用的数据保护要求。
