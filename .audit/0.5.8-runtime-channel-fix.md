# 0.5.8 原生 Chromium 消息回调兼容

## 已确认与未确认

- 用户确认是在扩展 Service Worker 的 Network 查看，仍然只见 upload；不是看错 DevTools 窗口。
- 本地 0.5.6/0.5.7 的下载实现存在，但两个真实入口（background、whatsapp.content）的 onMessage 都直接返回 Promise。
- 项目使用 WXT 0.21.4；其 browser 是原生 API 导出，没有 webextension-polyfill。
- Chrome 官方文档说明 Promise 监听器支持依赖新版内核及逐步启用；官方推荐兼容模式为 sendResponse + return true。WXT 升级文档明确指出取消了 Promise 返回的兼容支持。
- 尚未取得用户 AdsPower 当前内核版本和 Console 报错，不能宣称此缺陷就是该环境缺少 download 的唯一原因。

## 修复

- 公用 respondToRuntimeMessage：监听器同步返回字面量 true，通过 sendResponse 交付异步结果/错误；后台和页面两个方向都修复。
- 面板遇到空响应或通信错误时返回明确错误，避免 refreshData 因 undefined.ok 中断而一直显示旧状态。
- 设置卡片显示实际同步阶段，包括本地会话检查（尚未下载）、download 请求、页面资料写入、增量上传。
- 保留 0.5.7 的完整资料核对、消息增量、失败断点及防重复规则。

## 验证

- 针对真实入口注册的监听器，使用 callback-only Chromium 的契约测试：修复前 5 失败 / 1 通过，修复后 6 全通过。
- 新增完整链路测试：通过后台真实消息监听器接收 cloud:sync-all，回调确认后触发真实同步管理器的 download；空上传队列也恢复标签备注，无 upload 回传。
- TypeScript 与全量测试通过：153 通过，1 个生产只读诊断默认跳过。
- 使用 `.audit/verify-background-bundle.mjs` 直接执行构建后的 background.js，模拟原生 Chromium 回调契约：收到同步命令后 2 次 download、标签/备注/合作资料落地，0 次 upload。全程离线，无真实浏览器操作或生产写入。
- 用户确认 Service Worker Console 没有红色错误；真实环境停在哪一步仍需新版可见的同步阶段确认。
- 不修改生产云端数据，不更改账号或删除缓存。
