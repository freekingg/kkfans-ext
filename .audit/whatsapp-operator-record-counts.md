# WhatsApp 操作员会话记录统计修复

## 需求口径

用户确认：统计只按操作员汇总会话记录，不判断联系人号码。按天时仍使用首条消息时间，不用同步时间或上传时间替代。

## 修改范围

- nest-vue-admin/apps/server：每日统计移除号码必填和按号码合并；按账号空间下的会话 ID 识别同一条持久记录，不同记录逐条计数，再汇总到操作员和日期。
- 列表和导出取消号码、IG、头像导致的额外折叠，使用和统计相同的筛选记录。不会删除或合并数据库数据；旧数据中不同 ID 的记录会如实展示。
- 统计不再通过同号码扩展到不符合标签等筛选条件的记录，查询不受列表分页影响。
- 不选创建日期时，图表自动覆盖筛选结果的首聊日期，不再悄悄截断成近 30 天。仍保留最多 366 天的图表保护，超过时需明确选择日期范围。
- 今日、昨日、最近 3/15/30 日摘要继续固定按业务时区的今天计算，不随全历史图表区间移动。
- nest-vue-admin/apps/web：图表标明按会话记录计数；有缺失首聊时间的记录时显示一行提示，不制造日期。
- 不改插件，不改 schema，不执行云端数据修改或部署；原来的上传幂等和删除流程未改动。

## 验证

- 新增 7 个服务端回归场景，修改前 6 个失败、1 个通过；包括 16 条记录中 7 条无号码导致旧版只统计 9 条的复现。
- 修复后该场景列表、每日总数、操作员总数均为 16。
- 覆盖相同号码不同会话、多操作员、同会话 ID 跨账号、缺时间、超过 30 天历史、固定摘要窗口及标签筛选。
- 更新原先“按手机号去重”的测试契约，保留精确记录去重、时区、夏令时、日期边界和分页测试。
- 服务端 WhatsApp 相关测试 139 通过；web WhatsApp 相关测试 49 通过。
- 服务端生产构建、web 生产构建及 web 类型检查通过。
- 未逐条核验线上 kkflow05 的 16 条真实记录，测试使用合成数据，不声称线上已经生效。

## 发布

需要发布 nest-vue-admin 的 server 和 web；无需更新插件或运行数据库迁移。

```sh
pnpm --dir apps/server build
pnpm --dir apps/server pm2:reload
pnpm --dir apps/web build
```

将 apps/web/dist 发布到原 web 静态站点目录。不要卸载插件或清理缓存数据。
