# 云端恢复与双向同步：实现与验收记录

## 当前状态

- 原实现只有上传，没有下载恢复，卸载导致本地缓存丢失。
- 用户已明确授权本次不逐阶段询问，按先测试再实现连续完成。
- 已实现账号隔离下载、分页断点、三方资料合并、增量上传及服务端版本校验，复用现有 Prisma 表，无新增 migration。
- 标签、备注、合作资料和 SOP 数据恢复到 chrome.storage.local；消息恢复到 IndexedDB，保持原消息时间。
- 自动化测试覆盖空安装、旧接口、下载失败重试、后台重启、账号隔离、冲突处理和防止回传循环；部署后仍需在真实 AdsPower 环境验收。

## 数据模型与边界

优先复用现有 Prisma 模型，不新增业务表：

- WhatsappSyncClient：账号空间和标签定义。
- WhatsappConversation：会话身份、标签、备注、完整合作资料、SOP 阶段、消息时间及历史边界。
- WhatsappMessage：已上传消息正文与排序所需字段。
- WhatsappConversationStageHistory：阶段变更历史。

下载转换 DateTime 为毫秒时间戳、Decimal 为 number，保持插件现有数据结构；包含 additionSource、invitationUrl、followerData 等所有资料字段。
不下载软删除会话；不把本地删除消息操作转换为云端删除；不上传 AI Key、模型配置或其他本机设置。

## 接口与流程

1. 按 username（保留大小写）和规范化 WhatsApp 号码严格隔离所有查询。
2. 新增有上限的分页恢复接口：先会话资料，再消息与阶段历史；使用稳定游标，防重复和漏页。
3. 首次配置、重装后启动、手动同步先执行下载恢复；恢复完成后才处理本地待上传队列。
4. 下载失败、接口未部署、超时或 429 时明确提示；保存进度以便重试，不放行未经恢复的空资料上传。
5. 云端写回本地不进入上传变更队列；恢复的消息不作为新采集消息全量回传。
6. 恢复过程中出现本地修改时保留修改；不能由延迟返回的数据覆盖用户刚写的备注或标签。
7. 同步操作串行合并，快速切换会话或多次点击不产生并发恢复；账号改变后旧请求结果不可写入新空间。
8. 现有本地数据库未按账号分库，必须补上明确的空间绑定/隔离措施，禁止将旧空间本地数据上传给新账号。

## 防覆盖与冲突

- 区分“本地尚未恢复”与“用户主动清空”，不能用空数组/null 推断删除意图。
- 服务端旧客户端请求默认采取保留已有非空资料的兼容策略。
- 新客户端明确的资料变更应携带已读取的云端版本与修改意图；版本不匹配时返回冲突，先重新读取并合并，而非静默覆盖。
- 不影响消息增量 upsert、手机号/会话别名去重，以及消息创建/更新时间统计口径。
- 对无法安全自动合并的同字段冲突保留数据并提示，不静默丢弃。

## 插件 UI

- 配置页保留“保存并同步”“立即同步”，明确同步包含下载恢复与增量上传。
- 展示恢复中/恢复数量/上传中/完成/失败状态，失败可重试。
- 操作忙碌时禁用重复同步；恢复完成触发面板与列表更新，不需要重新给会话打标签。

## Red 阶段测试大纲

服务端：

- username + 号码隔离；号码格式规范化；参数校验；分页大小上限；软删除过滤。
- 全字段往返（包括多行粉丝数据、添加来源、备注、SOP 历史、消息和时间字段）。
- 多页稳定恢复、重复页、空空间；无鉴权沿用当前同步接口约定。
- 旧客户端空数据不清除现有标签/资料；显式清空与版本冲突；消息继续幂等。

插件：

- 全新安装从云端恢复；云端无数据时安全保留本地并上传。
- 恢复失败/404/429/超时不上传；重试从安全位置继续。
- 恢复消息去重和排序，不把恢复时间写成消息/业务创建时间。
- 云端写回不触发回传循环；新增消息仍保持增量。
- 恢复中编辑不丢失、账号切换不串数据、并发点击只执行一次。
- 旧版本本地数据升级保护；人工删除与未恢复的空值区分。
- 恢复后标签备注渲染正常，UI 状态及重复操作禁用。
