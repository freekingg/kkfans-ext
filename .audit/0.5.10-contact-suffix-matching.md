# 0.5.10 联系人号码后四位匹配

## 范围与规则

- 操作员用户名 + 博主号码后四位匹配；没有可识别的号码则使用抓取的联系人名称。
- 自己的 WhatsApp 账号数据空间规则不变：操作员用户名 + 自己的完整标准化号码。
- 后四位作为匹配键，不批量重算或截断持久会话 ID。完整号码保留用于展示和检查。
- 唯一候选复用原会话 ID、云端版本及消息 ID；不同完整号码出现多个同尾号候选时拒绝自动合并。服务端原有的“完整号码相同的历史重复记录”兼容归并逻辑保留。
- 仅后四位无法证明是同一个人。只有一个候选时仍按用户要求匹配，不能保证识别出从未同时出现/尚未存储的同尾号不同联系人。

## 修改

- 服务端上传在原账号空间内读取候选，标准化号码后比较后四位，兼容 contactWhatsappKey 尚未回填的旧记录。不修改数据库 Schema，不迁移线上数据。删除语义随后由 0.5.11 调整，见 `.audit/0.5.11-delete-no-tombstone.md`。
- 插件新增轻量联系人匹配索引。恢复、账号配置、联系人资料或消息记录身份变化后刷新；索引按 ID 排序，无身份变化不写入、不触发列表重渲染。
- 聊天列表、当前会话、上传前校验、云端恢复采用同一匹配规则；后台发现旧 DOM ID 已过期时先刷新索引并拒绝该次写入。
- 云端单页和跨页检查同尾号多个联系人，避免覆盖标签、备注、资料及版本基线。跨页失败保留已安全写入的前页，不应用冲突页，也不继续上传。
- 同屏看到不同号码、相同尾号的两个会话时，不挂载混淆标签，当前会话提示人工核对。
- IndexedDB 写事务拒绝并发捕获创建新的异号同尾号记录。原本未同步但与下载消息完全相同的内容标记为已确认；真正不同的本地修改继续保留。

## 发布

先部署 nest-vue-admin 的 server，再覆盖更新插件到 0.5.10，刷新 WhatsApp 页面并执行“恢复并同步”。不需要卸载扩展或清空本地数据。本次没有新增数据库迁移。

服务端构建/重启（在 nest-vue-admin 根目录）：

```sh
pnpm --dir apps/server build
pnpm --dir apps/server pm2:reload
```

本次未改 Web 前端；此前的折线图修复若尚未发布，需要单独更新 Web 构建产物。
