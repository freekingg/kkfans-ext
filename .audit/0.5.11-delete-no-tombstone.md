# 0.5.11 删除记录不再参与同步校验

## 用户确认的语义

- Web 端删除即彻底删除，不保留用于阻止插件的墓碑。
- 已删除记录不能参与联系人尾号、名称、Instagram 身份或资料版本校验。
- 插件中未改变的旧本地副本不会因后台定时检查自动复活；再次修改联系人或手动“恢复并同步”时允许作为新记录上传。

## 实现

- Web 删除接口由设置 `deletedAt` 改为物理 `deleteMany`；关联消息和 SOP 阶段历史按现有数据库外键 `ON DELETE CASCADE` 一并删除。
- 上传事务首先物理清理该账号空间内旧版本留下的软删除记录，再仅查询 `deletedAt: null` 的有效会话。旧墓碑不会参与后四位或资料版本判断。
- 插件单会话变动入队前清除该会话旧的 `cloudSkippedConversations` 标记；手动恢复清除全部旧标记。未发生变动的旧标记在后台启动时仍暂停，避免无操作自动复活。
- 兼容尚未更新的旧服务端：若其仍返回 `skipped: deleted`，插件继续临时记录跳过；后续修改仍可再次尝试。
- 设置页和 Web 删除确认文案已更新。

## 数据影响

- 新删除操作不可恢复，会物理删除会话、消息和 SOP 历史。
- 部署新服务端后，任意一次该账号空间的上传会清理历史软删除墓碑及其关联消息。这是将旧删除语义迁移为新语义的一次性兼容处理。
- 未新增数据库字段或迁移文件。

## 验证

- 服务端 WhatsApp 13 个测试套件、143 项测试通过，生产构建通过。
- 插件 42 个测试文件、174 项测试通过，1 项生产只读诊断默认跳过；TypeScript 检查通过。
- Web WhatsApp 页面 9 个测试文件、49 项测试通过，生产构建通过。
- 未部署服务器、未操作生产数据库。

## 发布顺序

1. 部署 server，使删除和上传不再使用墓碑。
2. 发布 Web 构建产物，使删除确认文案与真实行为一致。
3. 覆盖安装插件 0.5.11，刷新 WhatsApp 页面。
4. 对当前已经修改但仍被跳过的联系人点击一次“恢复并同步”。
